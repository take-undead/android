# thermalcam（サーマルカメラ）

Blackview BL8800Pro に内蔵の FLIR Lepton 2.5 を使う、純正アプリ（MyFLIR）の代わりのアプリ。
純正アプリの「画面のズレ」「温度表現の調整が分かりにくい」「精度が悪い」を直すために作った。

## カメラの性能（データシートの値。アプリでは超えられない）

出典: FLIR「Lepton with Radiometry Datasheet」500-0763-01-09 Rev 110。部品番号 500-0763-01 は実機から CCI で読み出して照合した。

| 項目 | 値 |
|---|---|
| 画素 | 80 × 60、水平画角 50° |
| 更新 | 9 回/秒弱（輸出規制。VoSPI は 27Hz だが 3 回に 2 回は同じフレームの繰り返し） |
| 測れる範囲 | 通常（高ゲイン）−10〜140℃ / 高温（低ゲイン）−10〜450℃ |
| 絶対温度の精度 | 通常: ±5℃ か 5% の大きい方 / 高温: ±10℃ か 10% の大きい方（典型値） |
| 温度差の感度 | 50mK 未満（**温度の差**は細かく見える） |

## できること

| 機能 | 内容 |
|---|---|
| 温度の取得 | Lepton の TLinear で全画素の絶対温度を直接受け取る（通常 0.01K、高温 0.1K 単位） |
| 点の温度 | 既定は中央。画像をタップした所に十字を移す。3×3 画素の平均（1 画素より揺れが小さい） |
| 最高・最低 | 赤▲・青▼で位置と温度を出す |
| 色 | アイアン / レインボー / 白が高温 / 黒が高温。右に色の帯と温度（上端・中央・下端） |
| 表示する温度の範囲 | 自動（ちらつかないようゆっくり追従、最小幅 2℃）/ 固定。「調整」を押すと範囲のつまみが出て、動かすと固定になる。「範囲: 自動」で戻す |
| 測定範囲 | 通常 / 高温 / 自動切り替え。切り替えたら校正（FFC）し直す |
| 重ね合わせ | 熱画像のみ / 輪郭（可視カメラの細部の明暗を足す。FLIR の MSX と同じ考え方。2026-10-18 に強さを 2 倍に）/ **白線**（可視画像の輪郭を検出し、1 画素の白い線で描く。線にするのはその画面で輪郭の強さが上位 15% の所）/ 映像を半透明で重ねる |
| 位置合わせ | 「調整」を押すと「大きさ・左右・上下」のつまみ（常には出さない。不意に触れてずれるため）。初期値は画角の比から計算。「位置を戻す」で初期値 |
| 自動位置合わせ | 「調整」の中の「自動で合わせる」。大きさはそのままで左右・上下を探し、**提案として表示**する。「採用」で保存、「やめる」で元に戻す |
| 輪郭の強さ | 「調整」の「輪郭」つまみ（重ね方が輪郭・白線のとき）。輪郭: 明暗を足す倍率 1〜7 倍。白線: 輪郭の強さで上位 4〜34% の所を線にする。既定 0.37（輪郭 3.2 倍・白線 15%） |
| 記憶 | 色・範囲・測定範囲・重ね方・位置合わせ・輪郭の強さをまとめて 1〜5 番に記憶し、「呼び出す」で戻す（形 v2。前の v1 も読める） |
| 温度校正 | 手動の FFC（シャッターで画面のむらを取り直す。位置は変わらない）。自動の校正中・校正推奨は状態の行に出る |
| 撮影 | **長押し**で撮影（短く触れただけでは撮らず「長押しです」と出す。撮ると端末が短く震える）。写真（印・色の帯・日時入り）を「ピクチャ/ThermalCam」（アプリ専用のフォルダ。普通のカメラの DCIM/Camera とは別）、全画素の温度（CSV、縦持ちの向き 60 列 × 80 行）を「ドキュメント/ThermalCam」 |
| 写真 | 「写真」ボタンで ThermalCam の写真を新しい順に一覧。タップで大きく表示し、左右にめくって前後へ。長押しで選んで「削除」（確認あり。同じ名前の CSV も消す）。アプリを消して入れ直すと、それより前の写真は一覧に出ない（Android の決まり。端末のギャラリーでは見える） |

- 画面が見えている間だけカメラの電源を入れる（裏に回ると切る。純正アプリが使えるように）。画面の回転では止めない。
- 画面のデザイン（2026-10-18 に作り直した。利用者「ダサい・無駄が多い・撮影ボタンの特別感が無い」）: ふつうのカメラアプリの作法。
  上 = 点の温度・最高・最低・センサー温度・色の帯 / 中 = 熱画像（状態は画像の下の端の小さな帯）/
  下 = アイコンの道具の列（色・範囲・測定・重ね・調整・記憶。名前に今の状態、有効なものは橙）と、
  左 = 最後の写真（押すと一覧）・中 = 丸いシャッター・右 = 温度校正。シャッターは押している間に輪が橙で一周し、一周で撮影・振動・画面が一瞬光る。
  短く触れたときは撮らず、シャッターの下の文字が橙で「長押ししてください」。知らせの帯は画面の上の方に出す（下だとシャッターを隠した）。
  アイコンは res/drawable/ic_*.xml の自作のベクター（事前の注意事項 #4）。
- 以前の画面の作り: 点の温度・最高・最低と横向きの色の帯は画面の上（横画面は右の欄の上）に置き、画像には印だけを重ねる。
  ボタンは小さく並べる。縦は画像が幅いっぱい、横は画像が高さいっぱいで右に操作。横にしても画像は景色と同じ向き。
- 権限は CAMERA（重ね合わせを選んだときだけ求める）のみ。

## 仕組み（2026-10-18 に実機と逆コンパイルで確かめた事実）

```
アプリ ──binder──> flir.lepton_camera_service（system_server の com.android.server.lepton.LeptonService）
                     ──binder──> ThermalCameraService（ネイティブ）──> /dev の lepton_drv（SPI）と I2C
```

- サービスは公開 API ではないので `android.os.ServiceManager.getService` を反射で呼んで IBinder を得る（純正アプリも同じ）。
  `open()` に呼び出し元の権限確認は無い。利用者は 1 人だけで、別の利用者が `release()` すると全員切れる。
- I2C のコマンド（CCI）は FLIR 公開の Lepton SDK の手順を Kotlin で書いた（`lepton/Cci.kt`）。FLIR の非公開ライブラリは使わない。
- **GPIO を VSYNC モードにしないとフレームが 1 枚も来ない**（FLIR のテストアプリの設定と同じにした）。
- readFrame = 164 バイト × 63 パケット（画像 60 行 + テレメトリー 3 行）。32 bit の値は下位ワードが先。
- 熱センサーの取り付けの向きは縦持ちの画面に対して 270°（利用者が手をかざして確認）。可視カメラは ID 2（サービスが返す値）。


## レンズと番号の対応（2026-10-18、レンズを 1 つずつ指でふさいで暗くなる番号を測った）

| レンズ | 番号 | アプリの名前 |
|---|---|---|
| 背面・一番大きいレンズ | ID 0 | メイン |

## センサーの正体（2026-10-18、カメラの下回り camerahalserver の記録で確認）

カメラを開くたびに、下回りが認識しているセンサーの一覧を記録に出す（NormalPipe の CreateInsatnce）:

| 下回りの番号 | ドライバ名 | 区分（DevId） | アプリの番号 |
|---|---|---|---|
| 0 | SENSOR_DRVNAME_S5KJN1_MIPI_RAW | 1 | ID 0 メイン |
| 1 | SENSOR_DRVNAME_S5K3P9SP_MIPI_RAW | 2 | ID 1 前面 |
| 2 | SENSOR_DRVNAME_GC5035_MIPI_RAW | 4 | ID 2 サブ |
| 3 | SENSOR_DRVNAME_GC032A_MIPI_RAW | 16 | ID 3 |

- /vendor/lib64 の調整用ライブラリは 7 種類（s5kjn1・s5kgm1st・imx376・s5k3p9sp・gc8034・gc5035・gc032a）。部品の載せ替えに備えたもので、実際に載っているのは上の 4 つ。
- **ID 3（GC032A）を開くと、下回りはセンサー番号 3 を 2592×1944（640×480 を要求したときは 1296×972）で動かすが、センサーから絵が 1 枚も来ない**
  （ISP の WAIT_IRQ の待ち時間切れ → error 4）。GC032A は 30 万画素とされる（型番からの推測）のに、設定は GC5035 と同じ大きさで、
  設定とセンサーが合っていないとみられる（推測）。ID 3 を開くたびに camerahalserver が再起動した（プロセス番号 31266 → 14497 → 14748 → 15220）ので、試験はやめた。
- 前に ID 3 で ID 2 と同じ映像が出た（21:08）理由は説明できていない。
- 背面 4 つのうち、一番大きいレンズの隣はサーマルの窓（熱画像でふさぐ試験）。4 つ目は ID 0・1・2・サーマルのどれでもなく、
  下回りの一覧で残るのは GC032A だけなので、4 つ目 = GC032A とみられる（推測。絵が来ないので映像では確かめられない）。
  仕様表の「200 万画素の深度カメラ ×2」は、実物では サーマルの窓 と 絵の出ない 30 万画素の GC032A。
- Android のセンサーの一覧（dumpsys sensorservice）に色・ちらつきのセンサーは無い（lib3a.sensors.color / flicker のライブラリはあるが使われていない）。
- 結論: アプリから使えるのは ID 0・1・2 の 3 台。ID 3 は下回り（メーカーのファームウェア）の問題で絵が来ず、アプリ側では直せない。

## カメラ画面の重さを直した（2026-10-18、利用者「切り替えがチラつき遅い、映像のラグとブレが酷い」）

| 変更 | 理由（測った事実） | 結果（測定） |
|---|---|---|
| 映像を TextureView に直接流す。白黒・緑・暗部は ColorMatrix | アプリで 1280×960 を画素ごとに計算していて毎秒 5.8 回しか出なかった | 毎秒 約 24 回 |
| 自動露出を毎秒 5〜30 枚に | [10,10] 固定で露出が長くぶれた。選べる範囲は 10・15・15〜20・20・5〜30・30（dumpsys） | 明るい部屋で 1/24 秒 |
| 画面の平均（ざらつき減らし）をやめ、写真だけ重ねる | 動くと尾を引いた | — |
| 前のカメラが閉じ終わる（onClosed）のを待って次を開く（CameraGate） | 閉じ終わる前に開くと error 2 → 0.6 秒待ってやり直し、その間画面を消していた | 切り替え 0.6〜0.7 秒（記録の時刻）、やり直し無し、ちらつき無し（利用者確認） |
| 暗部の初期値 0.5 → 0.2 | 新しい表示で明るい部屋だと白く飛んだ | — |

- 切り替えの時間は、自分のアプリの記録だけを試験中ずっとファイルに流して測った（カメラの下回りの大量の記録で、後からまとめて読むと消えていたため）。
- カメラサービスの「DIED client(s) with PID 979」の記録は、アプリを入れ直した時刻（lastUpdateTime 21:54:42）と一致した。入れ直しでアプリが終了した記録（他の 2 件は照合できず）。

## カメラ画面（「サーマル | カメラ」の切り替え）

普通のカメラ（メイン・広角・前面）。暗い所向けに露出を長く・感度を高くできる（赤外線の暗視ではない）。
- ライト（フラッシュの点けっぱなし。メイン・広角）。実機で点灯を確認（利用者の目視とカメラの記録 FIRED）。画面を閉じると消える。
- 画質: 標準（2560×1920 を 1・3・6 枚重ねる、暗部の補正を写真にも）/ 最高画質（カメラの JPEG を 1 枚。メイン 8000×6000・前面 4608×3456）。
- 前面は自撮りと同じく左右反転で表示。ピントが固定のカメラ（1・2）には自動ピントを指示しない。
- 撮影の失敗は理由を画面に出し、15 秒で打ち切る（前面の最高画質で 1 回だけ「保存中」のまま止まった。再現せず原因不明）。

## サーマルの追加機能（2026-10-18）

- 放射率: 「調整」の素材（肌 0.98・水 0.95・コンクリート 0.93・木 0.90・黒いゴム 0.94・黒い塗装 0.95・白い塗装 0.84・さびた鉄 0.65・磨いた金属 0.05）とつまみ。
  Lepton の RAD_FLUX_LINEAR_PARAMS の放射率を書き、読み戻して表示。実機で 1.00 → 0.50 にすると 32.2℃ → 41.3〜41.8℃（計算の見込み 41.5℃）。
  値は放射率表（ired.co.uk・ThermoWorks・Innova）の代表値で、表によって幅がある。背景温度は Lepton の既定 22℃ のまま。
- スポットメーター: Lepton 本体が点の周り 3×3 画素を測った値を 1 秒ごとに表示。アプリの計算と 0.1℃ 以内で一致（温度の読み方が正しいことの確認）。
- ざらつき減らし: アプリ側で温度を平均（弱 = 新しいフレームの重み 0.5、強 = 0.25）。
- 起動時に保存した設定を読み終わる前にカメラを開いていた（測定範囲などが既定値のままになり得た）のを、読み終わってから開くように直した（コードで修正。実機での差は未確認）。

## 暗所カメラ（2026-10-18 追加）

「サーマル | 暗所」の切り替えで、普通のカメラ（メイン ID 0 / 広角 ID 2）の高感度撮影にする。**赤外線の暗視ではない**。
- この端末に暗視カメラは無い（純正カメラは ro.hct_night_vision_id で暗視カメラを決めるが、この端末では未設定。4 台ともカラーのセンサー）。
- 手動露出の上限: メイン 0.16 秒・ISO 1100、広角 0.4 秒・ISO 2400（dumpsys）。自動露出は 1/14 秒・ISO 12000 のように公表の上限を超えた感度（デジタルの増幅とみられる）を使う。
- 実機の暗い部屋での明るさ（画面の平均 0〜255）: 自動 21.4、メイン最大 21.8、広角最大 22.4。**手動で最大にしても自動とほぼ同じ**で、暗所での伸びは小さい。
- 暗部の持ち上げは強すぎると黒いまだらが出たので上限を弱めた。撮影は 2560×1920 を 1・3・6 枚重ねて保存（night_*.jpg）。
- 暗所の間は熱カメラを止める。開くときに前の可視カメラが閉じきっていないと error 2 になるので、最大 5 回やり直す。

## 自動位置合わせの限界（2026-10-18、実機のデータを PC で調べた事実）

- 方法: 熱画像の「温度が急に変わる所」と可視画像の「明るさが急に変わる所」（ぼかしてから Sobel）の相関が最大になる左右・上下を探す。
- 大きさも探すと実行のたびに値が漂った（0.589 → 0.489 → 0.389）→ 大きさは今の値に固定した。
- 固定後は毎回同じ答えになったが、モニターの例では温度の境目（ベゼルの下端）ではなく明暗の境目（画面とベゼルの境）に合い、上下が 0.08 ずれた。
